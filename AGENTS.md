# Kaylee's Gamepack: guide for AI game builders

This is a learning app for **Kaylee, age 5**. She plays it on an iPad (saved to the home
screen). Her dad photographs papers from school (any subject: math, letters, phonics,
science like seasons or weather, social studies, feelings, holidays...) and opens a GitHub
issue. You turn that lesson into **a brand-new, fun game**, and he reviews it in a PR.

Kaylee loves **unicorns, the color pink, winning, and trophies with her name on them.**
She likes seeing and hearing her name. She **cannot read yet**.

## What you build: exactly one new folder

```
src/games/<game-id>/          # kebab-case, e.g. seasons-dress-up
  meta.ts                     # GameMeta (see below)
  Game.tsx                    # default export: React component taking GameProps
  *.tsx                       # any other components/stations you want
  assets/*.webp               # generated by `npm run art -- <game-id>`
  voice-lines.json             # every exact phrase that can be spoken
  voice/*.mp3                  # generated automatically by the workflow
art/source/games/<game-id>/*.png   # your full-size generated images (scratch, git-ignored)
```

The app finds games automatically (`import.meta.glob`). **Do not edit anything outside
your game folder**: not the shell, not the SDK, not other games, not package.json, not
workflows. No new npm dependencies. If you think the SDK needs something, build it inside
your game folder.

## The game contract

```ts
// src/games/<id>/meta.ts. Keep every string value on ONE line (a script parses this file).
import type { GameMeta } from '../../sdk'
import cover from './assets/cover.webp'

const meta: GameMeta = {
  id: 'seasons-dress-up',                  // same as folder name
  title: 'Dress Sparkle for the Seasons',  // short, fun, shown on the card
  emoji: '🍂',
  cover,
  subject: 'science: seasons',             // free text
  skills: ['name the four seasons', 'match clothes to weather'],
  vocabulary: ['season', 'winter', 'spring', 'summer', 'fall'],
  mechanic: 'drag clothing onto Sparkle, then sort pictures into season baskets',
  setting: "Sparkle's closet in a cozy treehouse",
  source: { issue: 12, pages: ['issue #12 photos'] },
  createdAt: '2026-10-02',                 // today's date, YYYY-MM-DD
  trophyTitle: 'Seasons Superstar',        // engraved under KAYLEE on her trophy
  debugLessons: [
    { id: 'spring', label: 'Spring dress-up' },
    { id: 'summer', label: 'Summer dress-up' },
    { id: 'sort', label: 'Sort by season' },
  ], // stable, unique ids; each starts a self-contained lesson
}
export default meta
```

```tsx
// src/games/<id>/Game.tsx
import type { GameProps } from '../../sdk'
export default function Game({ onWin, setProgress, debugStartLesson }: GameProps) { ... }
```

- Call `setProgress(done, total)` as she advances (fills stars in the top bar).
- Declare every independently testable lesson in `meta.debugLessons` in play order. When
  `debugStartLesson` is provided, start directly at that lesson with fresh state and set the
  matching progress. A jump remounts the game; no lesson may require state from earlier lessons.
  Keep delayed callbacks and async speech from an old lesson from advancing a new one.
- Call `onWin()` **once** at the end. The shell then shows confetti, a fanfare, and a gold
  trophy engraved **KAYLEE** + your `trophyTitle`, and saves it to her Trophy Room. Don't build
  your own ending/trophy screen.
- The shell draws a round 🏠 button (top-left, ~76px) and the stars (top, next to it) **over**
  your game. Keep ~100px clear at the top (`padding-top: calc(var(--safe-top) + 104px)`).
- Your game fills the whole screen (`position: absolute; inset: 0`). Must work in **portrait
  and landscape** on iPad (820×1180, 1180×820, 1024×1366) and not overflow. Size things with
  `min(..px, ..vw, ..vh)`.
- **Fill the screen** in both orientations: the play area should use the full height (flex: 1, center
  vertically, scale items up on tall portrait screens). No big empty bands. The school-paper example
  `unicorn-tea-party` uses a full-bleed scene with the action sitting on the table.

## Design rules (important)

1. **No reading required.** Every instruction is spoken with `say()`. Show short text too (for
   dad), with a `<SayButton text=... />` so she can hear it again.
   Add every possible exact `say()` phrase to `voice-lines.json`, including number variations,
   prompts, hints, the game title, and trophy lines. Keep random speech finite. The workflow
   generates the Sparkle character voice automatically; never use the iPad's built-in voice.
2. **No failing, ever.** Wrong answer → gentle wiggle + `sounds.oops()` + a spoken hint, then she
   tries again. After a wrong answer, *help* (count together, highlight the answer, narrow the choices).
   No timers that punish, no lives, no "game over".
3. **Short**: about 3–6 minutes total. 8–15 quick interactions, in 3–6 small rounds/stages.
4. **Big touch targets** (≥ 88px), one clear thing to do at a time, lots of juicy feedback:
   `sounds.*`, bounces, `burst()` confetti for mini-wins, `praise()`.
5. **Use her name** in spoken lines ("Great job, Kaylee!"). `KID_NAME` is exported.
6. **Teach what the paper teaches**: use its vocabulary words out loud, and turn its at-home
   activities into game moments (e.g. the math paper said "hop and clap the number", so the tea
   party game has "tap Sparkle 3 times to make her hop").
7. **Start easy, end a little harder** (e.g. the paper says "when 0–5 is easy, move to 6–10" → bonus round).
8. Kind, gentle, girly-cute tone. Pink/lavender/pastels. Unicorns welcome (Sparkle is the mascot).

## Make every game DIFFERENT

Dad does not want the same flow every time. Before designing, read `.lesson-input/existing-games.md`
(or run `npm run games`). **Pick a core mechanic and a setting that the recent games did not use.**
Don't copy the tea-party "stations on a rainbow path" structure. Invent a fresh shape of game.

**Not just a quiz.** A string of "pick the right card" questions is not a game. The core of every game
must be *hands-on play in a little world*: dragging, building, dressing, feeding, sorting, catching,
growing, decorating, finding things in a scene. Answer cards are fine as a small part, not the whole thing.
Give it a tiny story ("Sparkle's garden needs help before the party!") and a visible payoff that builds
up as she plays (the castle gets taller, the garden blooms, the snowman gets his hat).

Idea bank (mix, remix, or invent your own):
- **Feed the unicorn**: drag the right snack into Sparkle's mouth (letters, shapes, counts, healthy foods).
- **Pop the balloons / bubbles** that match (a sound, a number, a color word...).
- **Sort into baskets / bins** (`SortIntoBins`): seasons, living/non-living, big/small, first sounds.
- **Memory flip** (`MatchPairs`): letter ↔ picture, number ↔ dots, animal ↔ baby animal.
- **Dress-up**: dress Sparkle for the weather/season/job.
- **Build it**: build a castle/rainbow/snowman piece by piece by answering.
- **Catch falling stars/leaves/snowflakes** that match the target (gentle speed).
- **Paint / reveal** (`TapToReveal`): tap clouds away to reveal the answer picture.
- **Choose-your-path story**: Sparkle's adventure where each choice is a question.
- **Hide and seek**: find the hidden thing in a scene (tap the right spot).
- **Rhythm / dance**: tap along N beats, clap syllables.
- **Race**: each right answer moves Sparkle forward to the finish line.
- **Shop / bakery**: fill orders ("3 cupcakes please!").
- **Garden**: plant seeds, water, watch it grow in stages.

Subject examples to show the range:
- *Seasons* → dress Sparkle for each season, then sort pictures into four season baskets.
- *Letters / first sounds* → feed letter-cookies to Sparkle: "Find the one that starts with /b/!"
- *Shapes* → build a castle: tap the triangle for the roof, the rectangles for the walls.
- *Community helpers* → a parade: match each helper to their tool.
- *Feelings* → help plushie friends: "Bunny lost her toy. How does she feel?"

## SDK: `import { ... } from '../../sdk'`

The only shared thing games may import. Read `src/sdk/index.ts` and the files it exports;
try everything live at `#/playground` (run `npm run dev`).

| Import | What it does |
|---|---|
| `say(text, opts?) → Promise` | Speak out loud (awaitable). Interrupts previous speech unless `{ interrupt: false }`. |
| `sounds.pop / correct / oops / sparkle / whoosh / fanfare / note(step)` | Synthesized SFX. `note(0..10)` climbs a happy scale, great for counting. |
| `burst()` / `bigCelebration()` | Confetti. |
| `praise()`, `KID_NAME`, `numberWord(3)`, `wait(ms)`, `randomInt`, `pick`, `shuffle`, `sample` | Helpers. |
| `useAlive()` | `const alive = useAlive(); await say('..'); if (!alive()) return` in async scripts. |
| `useSayOnMount(text)` | Speak when a screen appears. |
| `<BigButton color size onClick>` | Chunky pill button. |
| `<ChoiceCards choices onCorrect onWrong? hint? size?>` | Big answer cards; wrong ones wiggle, right one bounces. |
| `<DragArea>`, `<Draggable onDrop onTap>`, `<DropZone id>` | Drag & drop. `onDrop(zoneId)` returns true to accept. Also support `onTap` as an easier alternative. |
| `<SortIntoBins items bins onDone>` | Drag each item into the right bin. |
| `<MatchPairs pairs onDone>` | Memory flip cards (halves can differ). |
| `<TapToReveal onDone>` | Tap clouds away to reveal a picture. |
| `<TapCounter count onDone>` | Tap something N times; says each number. |
| `<Mascot pose="wave" \| "cheer" \| "think" size>` | Sparkle the unicorn. |
| `<SayButton text>` | 🔊 hear-it-again button. |
| `<Scene bg>` | Full-screen background image wrapper. |
| `<StarProgress>`, `<Trophy>` | Used by the shell; available if useful. |

Styling: inline styles + CSS variables from `src/theme.css` (`--pink`, `--hotpink`, `--lavender`,
`--lavender-dark`, `--butter`, `--mint`, `--sky`, `--peach`, `--gold`, `--cream`, `--ink`, `--radius`,
`--shadow`, `--safe-top`). Font is Fredoka. Animations: `motion` (`import { motion, AnimatePresence } from 'motion/react'`).
Use `src/games/unicorn-tea-party/` as an example of code quality and structure, **not** as a template for game design.

## Art: generate your own with your image tool

Follow `art/STYLE.md` exactly (style prompt, sprites on pure white, backgrounds named `scene*`/`cover*`/`bg*`).
- Always make `cover.png` (square card art; include Sparkle using `art/source/mascot/wave.png` as reference).
- Usually 4–10 more images: a background scene and the sprites the game needs. Reuse the Sparkle poses
  from `<Mascot>` instead of redrawing her when you can. Emoji are fine for tiny extras.
- Save to `art/source/games/<game-id>/<name>.png`, run `npm run art -- <game-id>`, then
  `node scripts/contact-sheet.mjs src/games/<game-id>/assets` and **look at** `/tmp/contact-sheet.png`.
  Regenerate anything that cut out badly.
- Never put text/letters/numbers inside generated images. Render letters and numbers with HTML text instead (crisp and correct).

## Checks before you finish

1. `npm run typecheck` and `npm run build` must pass.
   The workflow runs `node scripts/generate-voice.mjs` before these checks and commits the generated clips.
2. `npm run test` (Playwright smoke test: loads every game, checks for console errors, calls
   `window.__kaylee.win()`). It needs a local web server; if your sandbox can't open ports,
   skip it (CI runs it after you).
3. Re-read the design rules above. Is every instruction spoken? Is there no way to fail? Is it
   different from the recent games? Does it work in landscape?
4. For manual testing, open **For Adults** on the home menu, answer **2 × 10 = 20**, and turn on
   Debug Mode. In a game, tap **Debug**, answer again, and jump to each lesson. Check that each
   lesson starts correctly, progress matches its position, and the final lesson can reach the
   normal trophy ceremony. Turn Debug Mode off when finished.

## Local commands

```
npm run dev          # http://localhost:5173 (then #/game/<id> or #/playground)
npm run check        # typecheck + build + smoke tests
npm run art -- <id>  # PNG -> webp with background cutout
npm run games        # table of existing games
npm run icons        # rebuild app icons from art/source/icon-1024.png
```
